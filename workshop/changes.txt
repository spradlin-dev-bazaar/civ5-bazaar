[b]0.5.4[/b]
Renames Bazaar's mod and fixes three problems for players: loading a save with other mods switched on, a crash at random, and two crashes of one plugin at the same moment. Plugins built for 0.5.0 or later work with it unchanged.

For players:
[list]
[*]Bazaar's mod is now named "Bazaar 0.5 - Multi-DLL Mod Loader" in the game's Mods menu, in the MODS folder, and on Bazaar's Steam Workshop page. It was "Bazaar Multi-DLL Mod Loader". Each version of Bazaar — the first two numbers of a release, such as 0.5 or 1.0 — is a separate mod, and the new name says which version this one is. Bazaar 1.0 will come out later as a separate mod, on its own Workshop item, and a game saved with Bazaar 0.5 loads only with Bazaar 0.5. It is still the same mod, so a game saved with an earlier release of 0.5 loads with 0.5.4, and plugins made for Bazaar 0.5 still find it.
[*]When you loaded a save while a mod was switched on that affects saved games but that the save doesn't list, the game switched to the save's own mods but left most of them switched off, all but the first. Without Bazaar, the save then loaded with some of its mods quietly missing. When Bazaar was one of the mods left off, the game crashed. Watching a Hall of Fame replay that was recorded with mods switched on went wrong the same way. Now the save loads with all of its own mods that affect saved games, with no crash. A mod that affects saved games but that the save doesn't list, a plugin's mod included, ends up switched off, which is how the game is meant to work, so a plugin can't be added to a game saved without it. This fix is in place once Bazaar has been switched on since the game started.
[*]The game draws the screen and runs its turns at the same time. When plugins replaced parts of the game that run during both at the same time, the game could crash at random, in a different place each time. In one reported game it crashed every 10 to 25 minutes. Fixed.
[*]When a plugin crashed while drawing the screen and while running the turn at nearly the same moment, Bazaar could mix the two crashes up in its report, and both crashes could be added to Bazaar's list of the plugin's problems at the same time, which can damage the game's memory. Now Bazaar reports each crash on its own, shuts the plugin off once, and shows its pop-up about the plugin once.
[/list]
For plugin authors:
[list]
[*]Nothing plugins use was added, removed or changed, so plugins built for 0.5.0 or later keep working without a rebuild. Bazaar's mod ID is the same.
[*]The plugin template, in the SDK on the release's GitHub page, builds a plugin against a single version of Bazaar. Its build.cmd script finds the SDK made for the version of Bazaar that the mod depends on: the folder you give to build.cmd, otherwise the folder named in the BAZAAR_SDK_0_5 environment variable, otherwise the folder above the project. build.cmd fails when it finds the SDK of another version of Bazaar.
[*]After building, build.cmd checks the finished package for mistakes that would keep Bazaar from loading the mod. When build.cmd finds any such mistakes, it deletes the package and the build fails. It also prints a warning when the project still has the template's mod ID, name, author, description or DLL name.
[*]In the template, authors now set their mod's version in the mod's project file and their plugin's version in their own code.
[*]The template now depends on Bazaar under its new name, and its workshop description says "Runs on Bazaar 0.5.x." and tells players to subscribe to Bazaar 0.5 - Multi-DLL Mod Loader.
[*]The SDK guide has a new section, "A build for a new Bazaar version". When a new version of Bazaar comes out, you make a separate build of your plugin for it, from its own branch or checkout, with a new mod ID and a name that includes the version, such as "Score Doubler (Bazaar 1.0)". For a version that is on the Steam Workshop, the build goes up as a new Workshop item, and the old item stays up, so games started on the older version keep the plugin.
[*]Lua mod authors get the same build.cmd and package check in the Claude Code plugin's Lua mod template.
[*]The developer docs' pages now name their version in their header, such as "Bazaar 0.5 developer reference".
[*]For those who build Bazaar itself from source: each version of Bazaar now has its own git branch, and 0.5.x is the branch of Bazaar 0.5.
[/list]
This is plugin API version 0.5.

[b]0.5.3[/b]
Fixes one problem for players: Continue on the Plugins screen passed over a DLC pack's own Advanced Setup. Plugins built for 0.5.0 or later work with it unchanged.

For players:
[list]
[*]When a DLC pack brings its own Advanced Setup screen, as some mods installed in the game's DLC folder do, Continue on the Plugins screen now opens that screen, as the game does without Bazaar. Before, it opened the game's own. An active mod's Advanced Setup still comes first.
[*]When no pack or mod brings its own, Continue now opens the game's Advanced Setup in the layout the game itself uses with Brave New World, not the Gods and Kings one.
[/list]
For plugin authors:
[list]
[*]Nothing plugins use was added, removed or changed, so plugins built for 0.5.0 or later keep working without a rebuild.
[*]The in-game checker in the SDK, on the release's GitHub page, has a new step, hand_over: a checks file can leave the game to you, or to another program, part way through a run, then take it back and play its last steps. Lua mod authors get the same in the Claude Code plugin's Lua mod template.
[*]The checker now finishes its run, closing the game and putting everything back, when the program reading its output stops part way.
[*]For those who build Bazaar itself from source: the hook generator can run outside Windows, and a generator run that fails no longer keeps the hook numbers it gave out.
[/list]
This is plugin API version 0.5.

[b]0.5.1[/b]
Fixes one problem for players: another mod could hide the Plugins screen. Plugins built for 0.5.0 work with it unchanged.

For players:
[list]
[*]A mod that replaces Advanced Setup and was installed or updated after Bazaar no longer hides the Plugins screen. When such a mod is turned on, the first Next in Mods takes about 15 seconds longer: Bazaar switches the mods off and on again so that its Plugins screen comes first. If the other mod's screen still comes first, a pop-up names the mod and says how to fix it.
[/list]
For plugin authors:
[list]
[*]Nothing plugins use was added, removed or changed, so plugins built for 0.5.0 keep working without a rebuild.
[*]The SDK guide, on the release's GitHub page, has a few new notes: say in your mod's description when your plugin must be above or below another on the Plugins screen; to change what a function written in a header does, hook the functions that call it; how a plugin's Lua part can use the game's own save data; call other plugins only through Bazaar; what happens when a replacement crashes; and that Bazaar catches only crashes.
[/list]
This is plugin API version 0.5.

[b]0.5.0[/b]
The first public release. From this release on, what plugins use only grows until the next major version.

For players:
[list]
[*]Plugins can keep their own data in your saved games, so when you load a game, its plugins carry on where they left off. If you turn a plugin off for a while, Bazaar keeps its data in your saves until you turn it back on.
[*]When a plugin crashes during a game, a pop-up names it and sends you back to the main menu without saving, since the game may be damaged. Load your last save or autosave to play on. If another mod saves the game after a crash anyway, loading that save warns you.
[*]Bazaar loads each plugin from the mod you turned on, even with several versions of a mod installed, and from folders whose names hold any characters.
[*]Bazaar refuses a plugin whose mod isn't marked as affecting saved games, since it would not come back when you load a save. The Plugins screen says why.
[*]Games saved with earlier pre-releases may not load. Start a new game with 0.5.0.
[/list]
For plugin authors:
[list]
[*]Every plugin must be rebuilt with the 0.5 SDK: Bazaar 0.5 refuses plugins built for earlier releases. From 0.5 on, what plugins use only grows within a major version.
[*]Plugins can keep data of their own in saved games, and values on every player, city, unit or plot, such as a kill count on every unit. A plugin can publish a value for other plugins and Lua mods to read, and mark it to carry over when the game replaces a unit or city, as for an upgrade or a capture. Lua mods read published values with Game.GetPluginValue. When one plugin replaces a function where another plugin's values carry over, Bazaar holds one of them back, as it does for hand-placed hooks.
[*]Plugins can publish plain functions for other plugins to call through Bazaar. Another plugin finds one by the publisher's mod ID, plugin ID, name and type, and calls it inside Bazaar's crash guard, so a crash counts against the plugin whose function crashed. Two plugins of one mod that both publish functions need plugin IDs of their own.
[*]A plugin's crash during a game now ends the game: Bazaar's pop-up names the plugin and returns the player to the main menu, and nothing is saved in between.
[*]Two new hand-placed hooks, UnitReplaced and CityReplaced, run when the game makes a new unit or city in place of an old one. NotificationAdded also passes the notification's lookup index, which CvNotifications::Dismiss and Activate take.
[*]The functions Bazaar loads plugins and saves their data from can no longer be hooked.
[*]CivHooks.h declares the exact type of every hook, so a hook with the wrong parameters fails to compile instead of crashing the game.
[*]Plugins' Lua functions run inside Bazaar's crash guard, so a crash in one is caught like a crash in a hook instead of taking the game down.
[*]The SDK and the developer docs are updated, on the release's GitHub page. The guide has new sections, "Keeping data in saved games" and "Calling another plugin's functions", and the template shows both kinds of saved data. The docs mark what was added or changed in 0.5.0.
[*]The Claude Code plugin's scaffold scripts refuse a comma in a mod's name and edit the project file with an XML reader, and its Lua event list is corrected.
[/list]
This is plugin API version 0.5.

[b]0.4.0[/b]
For players: nothing changes in the game itself, and games saved with Bazaar 0.3.0 still load after you update.

For plugin authors:
[list]
[*]Plugins can now read a notification's type, its map position and its extra game data, through 4 new functions on a player's notifications. Each is also a new hook point.
[*]The hand-placed hook for a unit's cancelled orders now runs before the orders are cleared when the unit earns a promotion, as it already did for every other reason, so a plugin can still read where the unit was going.
[*]Nothing plugins use was removed, so plugins built for 0.3.0 still load without a rebuild.
[*]The SDK and the developer docs are updated, on the release's GitHub page; the docs mark what was added or changed in 0.4.0.
[/list]
This is plugin API version 0.4.

[b]0.3.0[/b]
The first release.

For players:
[list]
[*]Run more than one DLL plugin for Bazaar at a time. Each plugin is an ordinary mod with a DLL inside. Turn on the ones you want in the Mods menu.
[*]A Plugins screen, in place of Advanced Setup, shows which plugins loaded and which were refused and why, and lets you change their load order or skip one.
[*]If a plugin crashes, Bazaar turns it off until you return to the main menu and tells you; the game keeps running.
[*]whoward69's Various Mod Components (VMC, version 97) are included, so mods that need VMC work.
[/list]
For plugin authors:
[list]
[*]Hook points: run your code before or after almost any engine function, or replace it.
[*]6 hand-placed hooks inside engine functions, for moments a function boundary doesn't catch, such as a notification being added or a unit's orders being cancelled.
[*]The engine's functions and shared variables are exported, so a plugin can read and change players, cities, units and plots directly.
[*]The SDK: the engine's headers, the import library, the compiler settings Bazaar is built with, and a template plugin to start from, with a guide. It's on the release's GitHub page.
[*]The developer docs: a page for every engine function, class and file, with a Markdown copy of each page.
[/list]
This is plugin API version 0.3.
