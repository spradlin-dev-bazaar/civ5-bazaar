The build-time generator that writes a hook wrapper for every engine function, `CivHooks.h` with the types of each hook point's hooks for plugins, the host's export list, and the list of functions that contain each hand-placed hook.

`layouts.py` is the layout check: it compares every class that the SDK's headers define, with its fields' types and its virtual functions' parameters, and every enum value of the game's headers and `CivPluginApi.h`, against the record in `class-layouts.txt`. Class templates are checked only through the sizes of their uses. `layout_types.py` reads the types and values with the libclang that `requirements.txt` pins. A version of Bazaar may change a class layout or an enum value that plugins see only when it has no release yet, that is, when the version in `CivPluginApi.h` comes after the version of the last release tag in the branch's history. The developer then runs `build-hooked.cmd accept-layouts` and rebuilds every plugin. Once a version has a release, its later releases can't change a layout, because plugins built against an earlier release of that version would break. The change then belongs in the next version of Bazaar, on its own branch, before that version's first release, as the layout check's message explains.

The build marks each engine function and global variable for export one at a time, in its generated copy of the engine, rather than marking whole classes: marking a class makes the compiler build member functions the game never uses, and some of those don't compile. A DLL can export at most 65,535 names; Bazaar 0.5.0 exports about 15,200, listed in `tools/released/exports.txt`.
