# Developer docs

`build-docs.cmd` builds the developer docs site into `CvGameCoreSource\BuildTemp\docs`. Beside each page is a Markdown copy, for coding models to search.

Three hand-written files in `docs\` add to it: `docs\task-guide.md` is the front page's guide, `docs\class-summaries.md` holds the class summaries, and `docs\function-notes.md` holds notes on single functions, one `## name` section per function, shown on that function's page. In all three, `[[name]]` links to a function, class or hand-placed hook by name, and `[[name|text]]` shows other text for the link; the build stops if a name does not match exactly one of them.

The docs are built on the developer's machine, never by GitHub, because the generator reads the engine with Visual C++ 2008's headers, which GitHub's build machines don't have. When a release is published on GitHub, the Action in `.github/workflows/docs.yml` runs twice. The copy of the Action on the release's branch only asks the copy on the default branch to run, and the copy on the default branch builds the whole site from the releases' docs zips with `gather_site.py` and publishes it on GitHub Pages. So a developer who changes how the site is built changes the copy on the default branch and copies the changed files to every version's branch, through one pull request for each branch, because `release.py prepare` and `release.py publish` both check that `docs.yml` and `gather_site.py` on the version's branch are the same as on the default branch and fail when they differ. Every file in a docs zip goes on the site except the Markdown copies of the pages, which stay in the docs zip. The Action can also be run by hand from the Actions tab on GitHub, with "Run workflow" on the default branch. Because the Action runs on its own only when a release is published, after the developer changes a release's "Set as a pre-release" checkbox on GitHub, or deletes a release, the developer runs the Action by hand so that the site matches the releases again. For the Action to publish the site, the repository's Pages setting must deploy from GitHub Actions, and its `github-pages` environment must allow deploys from the default branch. When the default branch changes, at 1.0, that setting must change with it.
